# Fable 5 Starter Kit — เริ่มโปรเจคใหม่ใน 2 นาที

## ติดตั้ง (ครั้งเดียวต่อโปรเจค)
1. copy ทุกอย่างในโฟลเดอร์นี้ไปวางใน root โปรเจคใหม่
2. เปิด terminal ในโฟลเดอร์นั้น (พิมพ์ `cmd` ใน address bar ของ File Explorer) → พิมพ์ `claude`
3. เช็ค: `/memory` เห็น CLAUDE.md · `/skills` เห็น fable ครบ 8 ตัว
(ทางเลือก: ย้าย `.claude/skills/` ไปไว้ `C:\Users\<ชื่อ>\.claude\skills\` ครั้งเดียว ใช้ได้ทุกโปรเจคตลอดไป)

## วิธีสั่งงานให้ได้ของดี (สำคัญกว่ากฎทุกข้อ)
คุณภาพงานขึ้นกับคำสั่ง 70% ขึ้นกับโมเดล 30% — สูตรคำสั่งที่ดี:
1. **เป้าหมาย ไม่ใช่วิธีทำ**: "อยากรู้ว่าออเดอร์ไหนจะส่งไม่ทัน" ดีกว่า "เพิ่ม column สีแดง" — ให้โมเดลเสนอวิธี
2. **แนบของจริงเสมอ**: ไฟล์เวอร์ชันล่าสุด, screenshot error, ตัวอย่างข้อมูล — ห้ามให้มันทำจากความจำ
3. **บอกเกณฑ์ตรวจรับ**: "ถือว่าเสร็จเมื่อ..." 2-3 ข้อ ชัดกว่าคำว่า "ทำให้ดีๆ" สิบเท่า
4. **สั่งทีละก้อน**: 1 คำสั่ง = 1 เรื่อง งานใหญ่ให้มันเสนอแผนก่อนแล้วค่อยอนุมัติ (กฎ Plan→Approve มีอยู่แล้ว)
5. **ทักทันทีที่เห็นผิด**: อย่าปล่อยผ่านแล้วมาแก้ทีหลัง — และสั่งให้จดลง MEMORY.md ทุกครั้ง
6. **คำสั่งพิเศษที่กฎรองรับ**: "งานนี้ใช้โหมดลูกน้องเต็มรูปแบบ" (บังคับ orchestrator) / "งานนี้ R0 นะ" (บังคับถามก่อนทำ)

## เลือกโมเดลให้คุ้มเงิน
- **Sonnet เป็น default** ของงานประจำวัน: แก้ bug, เพิ่มฟีเจอร์, งานเอกสาร — กฎ+skills ชุดนี้ออกแบบให้ Sonnet ทำงานได้ดีเช่นกัน และถูกกว่า Opus หลายเท่า
- **Opus เฉพาะ**: ออกแบบสถาปัตยกรรมใหม่, งานที่ Sonnet ติด 2-3 รอบแล้วไม่หลุด, ตัดสินใจใหญ่ที่ถอยยาก

## นิสัย 3 อย่างที่ต้องรักษาไว้ (จาก Fable 5)
1. **commit ก่อนการแก้ใหญ่ทุกครั้ง** — git คือปุ่ม undo ที่ดีที่สุด (`git init` ครั้งเดียว, `git add -A && git commit -m "ก่อนแก้ X"`)
2. **อย่าเชื่อคำว่า "เสร็จแล้ว" จนกว่าจะเห็นหลักฐาน** — ถามกลับเสมอว่า "ทดสอบอะไรไปแล้วบ้าง"
3. **spec.md คือสมองของโปรเจค** — ตราบใดที่มันอัพเดท เปลี่ยนโมเดล/เปลี่ยน session/หายไปเป็นเดือน ก็กลับมาทำต่อได้เสมอ
